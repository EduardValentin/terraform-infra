# GitHub Secrets Matrix

Primary management path: `infra/envs/controlplane` Terraform root.
Use `github_repository_variables`, `github_repository_secrets`, `github_environment_variables`, and `github_environment_secrets` inputs there whenever possible.

This document points to the sources of truth for secret and variable names. It avoids copying full generated backend payloads or workflow inventories.

## terraform-infra repository

### Required by Terraform workflows

- Terraform workflow secret names and environment mappings are defined in:
  - `.github/workflows/terraform-plan.yml`
  - `.github/workflows/terraform-apply.yml`
- `TF_BACKEND_CONFIG_*` values are generated by `scripts/terraform/render_minio_backend_configs.sh`.
- `TFVARS_*` contains the full environment-specific variable payload for the matching Terraform root.
- Backend setup and rotation details live in `docs/TERRAFORM_BACKEND.md`.

### Required by runtime secret sync

- Runtime secret sync secret and variable names are defined in `.github/workflows/sync-runtime-secrets.yml`.
- Runtime secret operation details live in `docs/RUNTIME_SECRETS.md`.

## Provider and control-plane values

These are typically carried inside `TFVARS_*`, not as separate GitHub Actions secrets:

- GitHub owner and PAT for control-plane management
- Tailscale tailnet name
- Tailscale OAuth client credentials used by Terraform provider
- bootstrap host pre-auth keys
- OPS Grafana admin password
- OPS Terraform backend credentials
- Hetzner token when PROD provisioning is enabled
- Cloudflare token and zone id only if public DNS is managed through Terraform

Control-plane variable names and defaults live in `infra/envs/controlplane/variables.tf`.
Use `infra/envs/controlplane/terraform.tfvars.example` as the example payload shape.

## course-platform repository

- Values managed by this repository are supplied through `TFVARS_CONTROLPLANE` and materialized by `infra/envs/controlplane/main.tf`.
- Values consumed only by application workflows should be checked in the application repository workflow files.

## Pinned SSH host key secrets

Use host key pinning secrets, not `StrictHostKeyChecking=accept-new`:

```bash
ssh-keyscan -H <test-node-hostname> 2>/dev/null
ssh-keyscan -H <prod-node-hostname> 2>/dev/null
```

Copy the full output into the host-key secrets consumed by `.github/workflows/sync-runtime-secrets.yml` and the application deploy workflows.
